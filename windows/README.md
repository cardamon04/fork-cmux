# cmux Windows desktop

This application runs interactive PowerShell terminals in a workspace sidebar with resizable horizontal and vertical splits. Select a pane to send input, use **Copy** with a terminal selection, or use **Paste** to send clipboard text to the selected pane. Closing a pane terminates its owned ConPTY process; closing the last pane removes that workspace. Closing the window ends all application-owned sessions.

Double-click a workspace row or choose **Rename workspace** to change its display name. Confirm with **Rename**, or use **Cancel**/close to keep the committed name. Names retain literal Unicode, punctuation and surrounding spaces; nonblank, well-formed text of at most 512 UTF-16 units is accepted without control characters. Duplicate names keep separate workspace identities. Renaming preserves the current pane and uses the existing version-1 layout `Title` field for save/normal-close/reopen. Unconfirmed input is not saved. No history or output persistence is added.

The selected terminal's live OSC 0/2 title appears in the application window caption. Titles retain literal Unicode and punctuation, with a 512 UTF-16-unit limit; invalid/control/whitespace-only values keep the previous title, and an empty value or terminal reset clears it. Updates publish the latest value at most every 100ms. Background panes retain their own title without selecting a pane or changing input focus. Selecting a browser or an empty terminal uses the ordinary application caption. Manual workspace names and saved session fields stay independent; live terminal titles are not persisted. Automatic workspace/tab naming and explicit title overrides remain unimplemented.

**Increase font size**, **Decrease font size** and **Reset font size** adjust the selected terminal's text. Each step changes one CSS pixel within 6–72 pixels; reset returns to the existing 14-pixel default. The renderer refits the grid within the existing 1,000-column/row native limit and updates that pane's ConPTY size without writing shell input. Neighboring terminals keep their own size; moving a live pane retains its size. Browser panes disable these terminal actions. Narrow toolbars expose them through the standard overflow menu. This is transient per-pane zoom: new panes use the default, and saved layout fields, Ghostty configuration, persistent font preferences and shortcuts are not added.

Each browser pane has a **Stop** button while a page navigation is loading. It cancels that pane's pending load; the committed document remains available when a new page has not yet committed. The status reports that loading stopped, and the next address, Back, Forward or Reload action can continue normally. Stop is disabled while idle, after requesting cancellation, during initial browser setup and after a renderer failure. It does not clear browser history or create a saved-history setting.

**Find in terminal** opens a search bar in the selected terminal. It searches literal text in that pane's retained output (up to 5,000 scrollback lines), including soft-wrapped text. Use the arrow buttons or Enter/Shift+Enter in the search field to move between matches, and **Match case** to distinguish letter case. The selected match works with **Copy**. Escape in the search bar or its close button clears highlights and returns terminal focus. Search text stays in the pane and never reaches the shell. Each pane retains its own search while switching workspaces; browser panes disable this terminal action. Search text is limited to 256 UTF-16 units and highlights to 1,000 matches; `≥ 1,000` indicates a capped count while navigation continues. Regular expressions, cross-pane search, persisted queries and an application-wide find shortcut remain unimplemented.

**Move workspace up** and **Move workspace down** reorder the selected sidebar row by one position. The same workspace and pane stay selected; existing terminals, browser state and split layout remain live. The first row cannot move up and the last row cannot move down. Both actions are disabled with zero or one workspace. Narrow/localized toolbars can place actions in the standard overflow menu. The existing version-1 workspace array and selection index retain the order on **Save layout**, normal close and reopen. Drag/drop, pinned/groups ordering and movement between windows remain unimplemented; no ordering shortcut is added.

**Move pane to new workspace** detaches the selected pane from a split into a new, selected workspace in the same window. Its shell, terminal contents or browser page remain live; the source split collapses around its other panes. The new workspace uses the existing numbered naming sequence. A browser move selects its address field, matching the upstream GUI's focus intent. A workspace with only one pane cannot detach it. The action is also available in the toolbar's standard overflow menu. Save/normal close/reopen use the existing layout fields; shell/browser memory is not persisted. Moving to an existing workspace or another window, tab strips, automatic titles, drag/drop, CLI/API movement and a new shortcut remain unimplemented.

When a search control has focus, **Paste** inserts into the search field, removes line breaks and respects its length limit. **Copy** prefers selected search-field text and otherwise copies the selected terminal match. Selecting the terminal returns Paste to normal shell input.

**Open browser** creates a browser beside the selected pane, or a browser workspace when none remains. Enter an HTTP/HTTPS URL and use **Go** or Enter, **Back**, **Forward**, **Reload** and **Developer tools**. A bare website name defaults to HTTPS; localhost and loopback addresses default to HTTP. Browser panes retain their history when switching workspaces and share a browser profile within this application instance. The terminal's Copy/Paste toolbar actions are disabled while a browser is selected; browser keyboard/context-menu operations belong to the web control.

The application implements parts of F-01/F-02/F-03/F-06/F-10, not a complete Windows port. Persistent browser profiles, browser-data import, downloads, popup/new-window handling, permission grants, browser automation CLI/API, full session recovery, WSL/SSH integration, notifications, Ghostty settings and image protocols, configurable shortcuts, cloud/iPhone integration, installation and updates remain incomplete. Real OS IME composition and a full working day with real agents are not yet verified. There is no limit of ten live panes; ten is the initial concurrent terminal test workload.

## Run

Prerequisites: Windows, .NET SDK 10, Node.js 24, and the Microsoft Edge WebView2 Runtime. The app uses `pwsh.exe` from PATH if present and otherwise Windows PowerShell. It starts in the launch directory and loads the normal shell profile. It does not install a runtime, change Windows settings or require elevation.

The selected terminal's last confirmed local directory appears in the status bar (with its full path in the tooltip). New terminal splits start there. PowerShell 7 and Windows PowerShell 5.1 report changes through a session-local prompt wrapper and OSC 7; the existing prompt, command status, native exit code and error records are preserved in the tested scenarios. No profile file or execution policy is changed. Restricted language mode, read-only prompts or an existing integration-state variable leave the prompt untouched. Replacing the prompt later can stop reporting until the integration is installed again in a fresh shell.

Directory reports are untrusted metadata. Only existing local drive directories without reparse points are accepted; remote/UNC locations, query/fragment-bearing URLs, invalid escapes and redirected directories are ignored. The pane retains its previous confirmed directory when a report is refused. This does not establish WSL/SSH directory tracking. Reports select directory data only, never an executable, shell argument or environment value.

```powershell
npm ci --ignore-scripts --prefix windows/Cmux.Desktop
dotnet restore windows/Cmux.Desktop --locked-mode
dotnet run --project windows/Cmux.Desktop --no-restore
```

The renderer packages and WebView2 SDK are pinned with integrity lockfiles. No terminal assets come from a CDN at runtime. Assets are served only to `https://cmux-terminal.invalid`; external and frame navigation, popups, downloads and browser permissions are blocked in the terminal controller. Terminal output passes as data to xterm.js and never enters an HTML or JavaScript template. Clipboard access occurs through the native toolbar actions.

Temporary WebView2 profiles belong to this app instance and are removed after controllers and the browser process close. Existing browser profiles are not imported. Ambient profile-folder overrides and machine-policy redirects are refused. Terminal scrollback is not persisted between launches yet.

Web browsing uses a separate profile from the fixed-origin terminal renderer. Web pages have no WebView native message channel or host objects. Top-level browsing accepts HTTP/HTTPS and a blank page; file URLs and external application schemes are blocked. Popups, downloads and permission requests currently show localized notices and are declined. Browser data belongs to the temporary browser profile and is removed on application exit. The app does not open a remote debugging TCP port.

Opening a browser preserves a pane selected while startup is pending. A failed browser process shows a local recovery message; workspace switching, resizing and healthy terminals remain usable. Close the failed pane and open a browser again to recover. The app does not automatically reload or resubmit a failed page.

The status bar also shows the selected terminal's Git branch, or a 12-character commit ID for a detached HEAD. This requires Git for Windows on an absolute PATH entry with support for `--no-lazy-fetch`; Git is optional for running the terminal itself. Metadata refreshes after a directory/pane change and about every two seconds while a terminal is selected. Unborn branches, nested directories and linked worktrees use Git's own repository/ref discovery. Browser panes and unavailable, malformed or non-repository state clear the label. A fixed-width label keeps the full value in its tooltip. Paths and branch names render ampersands literally.

Git status is display-only and is not persisted. It does not check out a branch or contact a Git remote. Dirty state, PRs and ports remain unimplemented.

## Save and reopen a layout

The normal application saves its layout when its window closes and restores it at the next launch. **Save layout** also makes a checkpoint while working. The file is `%LOCALAPPDATA%\cmux-windows\session.json`. Workspace order, nested split directions/proportions, selected workspace/pane, terminal startup directories and browser addresses are retained. Terminal processes end on exit and restart as fresh shells; browser addresses reload in a fresh temporary profile.

The existing terminal `Directory` field now retains the confirmed local directory after PowerShell `cd`. Saving validates a snapshot of each pane's latest received report, so later reports cannot replace that checkpoint or require the stream to become idle. Shells without directory reporting retain their startup directory. Missing or redirected saved directories fall back to the current launch directory with a notice. Browser history, cookies, login state, scrollback, commands, drafts, live-process reattachment, agent resume, window geometry and crash-time autosave remain outside this partial F-10 implementation. Addresses containing URL user information reopen as a blank page. The local layout file contains the remaining browser URLs and paths; directory tracking adds no command/output/history/environment storage and does not change the file format version.

A lifetime file lease prevents concurrent app instances from overwriting the same session. An instance that cannot load the saved file shows a notice and leaves that file untouched, including malformed, oversized or future-version data. Correct the file or close the owning instance and restart to retry restoration. If saving on close fails, **Yes** retries, **No** exits without replacing the previous save, and **Cancel** keeps the current terminals running. A close during startup waits for initialization before saving and teardown.

An initialization failure also protects the previous save, even when the layout file itself was valid. A browser address restored from the file remains in the layout while its new page is still loading, so an immediate checkpoint or close retains that address. Terminal teardown waits for normal pseudoconsole closure and, if its original child is still alive after ten seconds, cancels that child through the retained process handle and awaits exit. It does not look up another process by PID.

`SessionStore` writes an owned temporary file, flushes it and replaces the session file on the same volume. The versioned layout has no executable, arguments, environment or resume-command fields. Loading rejects unknown or duplicate properties, unsafe URLs, nonlocal directory paths, invalid selection/tree data and excessive input before creating panes. Current storage bounds are 1 MiB, 64 workspaces, 256 panes and 16 nested splits; they protect restoration and do not truncate a larger live layout. A save beyond these bounds reports failure. Directory reparse points are not followed for storage or restored working directories.

## Test

```powershell
dotnet restore windows/Cmux.Desktop.Tests --locked-mode
dotnet build windows/Cmux.Desktop.Tests --no-restore --nologo -warnaserror
dotnet run --project windows/Cmux.Desktop.Tests --no-build -- desktop-results
dotnet run --project Prototypes/WindowsTerminal -- --self-test (Get-Command pwsh).Source
```

The desktop tests show their own application window and exercise toolbar actions, trusted Chromium keyboard/mouse input, selection and Copy, Ctrl+C, real interactive PowerShell/PSReadLine, Unicode, SGR rendering, resize propagation, pane/workspace isolation, teardown during output and ten live terminals. They use a temporary working directory and prompt, disable PSReadLine history persistence and point its history path to that directory, use `-NoProfile`, and inject an in-memory clipboard. They do not read or overwrite the user's clipboard. `terminal.png` captures only the application-owned renderer; it is not a screenshot of other desktop windows or proof of IME behavior.

Browser tests use a private loopback HTTP fixture and the real browser toolbar, page input/clicks, history/reload, native inspector window, same-origin cookies across separate profiles, host-message denial, workspace switching, closing during an unfinished load and reopening. `--browser-only [artifact-directory]` runs this focused workflow. No public website or real account is used. `browser.png` is a renderer capture; `desktop.png`, when supported by Windows PrintWindow, captures only this test application's window. These images do not establish IME or full browser parity.

`--browser-failures` runs the startup-selection and fatal-process regressions. It deliberately crashes only a test-owned browser after checking its PID and profile differ from the terminal's, then verifies UI dispatch, healthy shell output, recreation and profile cleanup. These checks also run in the full suite.

`--session-only [artifact-directory]` runs storage and actual native save/close/reopen scenarios. It verifies mixed nested layouts, hidden split proportions, selection, Unicode startup directories, browser reload into a new profile, failed-save preservation, the real native Cancel/Yes/No choices, early close, unsupported-data protection and owned teardown. `--session-store` selects just the file/lease/validation cases. Both are included in the full desktop suite. They inject only a private temporary session path and never read or write the normal application session. `session-restored.png` captures only the test-owned restored application.

`--session-regressions startup` verifies that a refused WebView initialization followed by normal close keeps the previous saved file byte-for-byte. `--session-regressions url` withholds a private restored page's response and verifies that both the toolbar checkpoint and normal close preserve its URL. Both also run in `--session-only` and the full suite. Session ownership checks retain the original process handles through close instead of reopening possibly reused PIDs. The transport suite's `powershell-close-during-startup` case closes four private shells before their ready markers and verifies actual process exit.

The focused `Cmux.Desktop.Tests.exe --packaging-and-locales` check verifies regional/script fallback, localized profile refusal, supported catalogs and the actual distributed WebView2 notice. It is also part of the complete desktop suite.

`Cmux.Desktop.Tests.exe --paste-limit` verifies that a permitted 32,768-character clipboard paste still reaches the shell when bracketed paste adds its protocol envelope. It uses a private clipboard fixture and leaves the pasted marker unexecuted, then closes that owned terminal. This check is also in the full suite.

`Cmux.Desktop.Tests.exe --search-only [artifact-directory]` exercises actual PowerShell output and the find toolbar/control paths: scrollback navigation, Enter/Shift+Enter, case filtering, selected-match Copy, empty/missing queries, Unicode, soft wraps, literal punctuation, input isolation, new output, workspace/browser isolation, dismissal, closing and the highlight cap. It uses the same private shell/history/clipboard fixture as the full suite, which includes these checks. `terminal-search.png` captures only that fixture's renderer. Unicode input here does not establish real IME conversion behavior.


`Cmux.Desktop.Tests.exe --rename-only [artifact-directory]` runs nine workspace-name checks: the row and toolbar paths, cancel/invalid/boundary/literal input, all nine locale controls and RTL direction, busy/nonrow events, duplicate names, browser and changed-selection isolation, explicit save, normal close/reopen and owned teardown. `--rename-regression` isolates the initial row workflow. They run in the full suite. Tests operate on owned WinForms controls/framework events and read owned native list text; they do not send global mouse/keyboard input or establish physical IME behavior. Optional `workspace-rename-dialog.png` and `workspace-renamed-sidebar.png` capture only owned controls.


`Cmux.Desktop.Tests.exe --ime-only [artifact-directory]` runs fourteen checks across PowerShell 7 and Windows PowerShell 5.1. Chromium's `Input.imeSetComposition` and `Input.insertText` emulate candidate updates, commit and cancellation in the actual renderer. Intermediate candidates must not reach the shell; the final Japanese/emoji text must reach `Read-Host` exactly once and match a complete UTF-8 response envelope. Search composition stays local. IME-processed Enter/Escape (`keyCode=229`, including `isComposing=false` boundary events) must preserve search selection/focus, while ordinary Enter/Shift+Enter/Escape still work. `--ime-enter` and `--ime-escape` isolate those key regressions. Both shells also repeat the key checks under an `ar-EG` renderer configuration, use the existing locale-aware count oracle, and restore the original configuration. `--ime-arabic` isolates the same keys in a private process whose UI culture is `ar-EG`; it does not change the OS language. These checks run in the full desktop suite; optional `ime-terminal-*.png`, `ime-search-*.png` and `ime-arabic-*.png` capture only the owned renderer.

This is browser composition emulation, not real Microsoft IME acceptance. Event trust varies with the CDP commit path and is recorded separately; it does not prove physical keyboard input. OS candidate windows, conversion, input-profile switching and candidate positioning remain unverified. The tests neither change OS/input-method settings nor use the user's profile/history/clipboard. Real IME verification requires proven foreground/focus ownership of the private fixture and an already enabled input method.

`--search-clipboard paste` and `--search-clipboard copy` isolate the native toolbar clipboard regressions while a search control owns focus. They verify that command-like clipboard text never enters PowerShell, that replacing a search selection stays within its limit, and that selected query text is copied. Both run in the focused search and full desktop suites using a private in-memory clipboard.

`--cwd-only [artifact-directory]` runs the local URI/junction boundary, reported-directory save regression and both real PowerShell versions through automatic cd, status display, split inheritance, pane/browser isolation, prompt status/exit/error preservation, report bursts, invalid reports and actual save/close/reopen. `--cwd-regression` selects the data-loss regression; `--cwd-shell pwsh` or `--cwd-shell windows-powershell` selects one integration. All run in the full suite with private `-NoProfile` shells, private history paths and synthetic output. The normal application's profile remains enabled. `working-directory.png` captures only the fixture's restored window. This does not verify real IME or all third-party prompts.

`--cwd-flood` confirms native receipt of the target directory, then saves while a private shell continues reporting that existing deep directory, checks the stored checkpoint and interrupts only that fixture. It also runs in the CWD/full suites. This is a live-load check; it is not evidence of a previously reproduced hang.

`--cwd-case` verifies that a case-only accepted report updates both the pane model and displayed directory. It creates ordinary private directories without changing filesystem case-sensitivity flags. Actual case-sensitive filesystem behavior remains unverified. The restored-path regression also runs in a narrow window and checks logical output across soft wraps. Desktop teardown checks retain the original owned process handles from registration through close, without reopening exited PIDs.

Integration checks decode the shell's actual provider path from a unique begin/end ASCII envelope and compare the UTF-8 value exactly, independently of legacy console text rendering. They still print the readable path; any mismatch is logged as a display coverage gap with the private rendered output and console codepage. A correct cwd value does not establish Unicode glyph/width parity. Both PowerShell versions capture their own restored fixture window (`working-directory.png` and `working-directory-windows-powershell.png`). `--cwd-oracle` checks both shells with an actual descendant directory and a different expected parent whose UTF-8 length is divisible by three, so a Base64 prefix cannot count as equality. These positive/negative controls also run in the CWD/full suites.

The UI catalog contains English, Japanese, German, French, Arabic, Spanish, Traditional/Simplified Chinese and Korean. The current Windows UI language selects a supported catalog, with English fallback. The terminal content follows the shell and font behavior.

`Cmux.Desktop.Tests.exe --git-only [artifact-directory]` verifies the real Git reader and both PowerShell versions: Unicode/literal unborn branches, same-directory branch changes, detached HEAD, linked worktrees, native status rendering, owned DOM focus, pane/workspace/browser isolation, malformed HEAD/non-repository clearing, live shell input, storage scope and normal close. `--git-regression` selects the original missing-label regression. These checks also run in the full suite. `git-status-pwsh.png` and `git-status-windows-powershell.png` capture only the owned native status strip, not WebView pixels or the user's desktop. They do not establish physical keyboard/mouse or real OS IME behavior.

`--git-render-regression` compares the actual selected label's native bitmap with a verified escaped-literal control. RenderItemText event arguments are reported after drawing and are not a pixel oracle. `--git-output-regression` runs the real reader in an owned child with a private copy of the test executable supplying fixed synthetic stdout above the output limit; the data must be rejected without an escaping exception. It does not create an oversized Git HEAD. `--git-worker-regression` reproduces the previously observed worker fault at the native lifecycle boundary and verifies that the original shell and profile are disposed before Shutdown reports the error. ## Boundaries and follow-up

`Cmux.Desktop.Tests.exe --workspace-order-only [artifact-directory]` runs the original ordering regression and a native mixed-session workflow: both directions and boundary controls, duplicate identity/literal native row text, live shell/browser focus and state, disabled toolbar actions, existing-schema explicit save, latest-order normal close/reopen, naming sequence and zero/one workspace. `--workspace-order-regression` selects the original missing-action case. All run in the full suite. Layout comparisons capture the actual restored split ratio before moving: integer pixel rounding can differ from the input seed's decimal ratio, and is not an ordering regression. The three `workspace-order-*.png` files capture only owned native sidebar/toolbar controls. Framework actions do not establish physical mouse/keyboard or OS IME behavior.

`Cmux.Desktop.Tests.exe --pane-detach-only [artifact-directory]` exercises live terminal/browser moves, nested source collapse, current ownership after repeated transfers, integrated `cd`, source-close isolation, disabled controls, existing-schema explicit save, latest-state normal close/reopen, and nine translations. A native `ControlAdded` failure checks that adoption rolls back the original live tree and naming counter, then the same pane can be moved successfully. `--pane-detach-regression` selects the original missing-action discriminator. The general desktop shell fixture has no prompt reporter; the directory scenario explicitly uses the production prompt integration and proves reports before moving. A failed post-move `cd` assertion records the existing report, selection and owned rendered output without resending the command. These tests run in the full suite. The four `pane-detach-*.png` files capture owned native sidebar/toolbar/popup/address controls; physical input and real OS IME remain unverified.

`--pane-close-terminal-regression` and `--pane-close-browser-regression` separately assert that ordinary split closure disposes the pane and its managed child controls and releases their native handles. They also run in the focused/full suites. Shell/profile cleanup alone does not prove WinForms control cleanup. Shared split removal keeps the closing pane under its old split until disposal; a live move transfers that control to the new workspace instead.

`--pane-detach-overflow-regression` displays the actual English overflow popup at minimum width with the toolbar focused, then verifies that the pane selected immediately before invocation is the one transferred. It records native activation changes while the toolbar is disabled. Disabling the toolbar must not replace the logical action target through native focus restoration. This case also runs in the focused/full suites.

`--pane-async-focus-regression` gates the existing asynchronous action wrapper and focuses the owned browser address field while the action awaits. Completion must retain that newer same-pane focus and selection. Toolbar focus projection happens synchronously before the action yields; an unavailable renderer's focus failure is reported without preventing a recovery action from running. This case also runs in the focused/full suites, using the existing private wrapper through test reflection rather than a production test hook.

`--unicode-input-regression` verifies raw Windows PowerShell 5.1 prompt input containing Japanese and a supplementary clover. It compares the actual engine history and provider CWD through complete UTF-8/Base64 frames; the command itself is entered as ordinary Unicode text. `--unicode-input-only [artifact-directory]` runs fourteen cases across Windows PowerShell 5.1 and PowerShell 7: mixed scalars and combining marks, cursor editing, Ctrl+C cancellation, multiline paste, protocol disable and fragmented re-enable, plus VT payload preservation (`--unicode-input-wire` selects that check alone). `--unicode-input-f3` selects two existing Ctrl+F3 compatibility checks before/after Unicode text, mode disable and renderer reset; unique callback markers and actual engine counters/errors avoid sharing a file with the writer. These cases also run in the full suite with private history/clipboard and original retained process handles. The PNG captures only the owned terminal renderer. Physical input, OS IME and general glyph/width parity remain unverified.

The renderer tracks ConPTY's DECSET 9001 request through xterm's parser. When requested, `ConPtyInput` sends non-ASCII text as documented Win32 `VK_PACKET` key records, avoiding legacy Alt+numpad key-up conversion. ASCII/control sequences, messages containing ESC or C1 controls, and bracketed-paste envelopes keep their existing path. The source UTF-16 content limit is enforced before packet expansion. No shell, profile, module, code-page or persistent setting change is needed. This adapts ordinary text input; Alt-prefixed Unicode and full Win32 keyboard/modifier reporting remain outside the implemented scope. See [Microsoft's protocol](https://github.com/microsoft/terminal/blob/main/doc/specs/%234999%20-%20Improved%20keyboard%20handling%20in%20Conpty.md).

`--terminal-title-core` dispatches before WinForms initialization and covers the pure live-title model, all nine catalog formats, real pinned xterm parsing/coalescing, and two owned background ConPTY producers. It does not construct a Form/WebView, use input devices or access the OS clipboard. `--terminal-title-only` adds actual GUI/native-caption, focus, storage and pane/workspace/move/browser checks; those also run in the full suite and require an isolated desktop. A core run does not establish native caption rendering or focus behavior. Target-PC GUI validation is pending while foreground interaction is restricted, and actual selector/hosted CI results must be recorded separately. `terminal-title-pwsh.png` and `terminal-title-windows-powershell.png`, when produced by that GUI workflow, capture only the test-owned application window.

`Cmux.Desktop.Tests.exe --browser-load-core` runs six pure navigation-state/locale cases before WinForms initialization. It does not construct a Form/WebView or access desktop/input/clipboard APIs. The full suite and `--browser-only` additionally exercise an actual held loopback request, engine cancellation, committed-document retention, history/recovery and two-pane isolation. Those GUI cases require an isolated desktop; target-PC execution remains pending while foreground interaction is restricted.

`--terminal-font-size-only [artifact-directory]` runs a fixed-font window-resize retention regression, the pinned renderer's font-option/buffer contract, nine translated action sets and both private PowerShell versions through actual renderer/ConPTY grid changes, native toolbar routing, pane/workspace/browser isolation, live moves and reset with pending Unicode input. These nine cases also run in the full suite. The Node contract also checks actual xterm scrollback behavior on row growth with explicit modern/older Windows-build fixtures. The two `terminal-font-size-*.png` files capture only the owned renderer. The Node contract runs with an inert DOM; it does not establish physical font metrics or focus. Target-PC GUI, physical input and real OS IME remain unverified.

The trusted renderer receives the host's Windows build and uses xterm's public ConPTY compatibility option. This keeps existing scrollback outside the viewport when ConPTY grows/repaints rows, and selects the renderer's supported reflow behavior for that build. It applies to ordinary window/pane resizing as well as font changes. No OS, shell, profile or persistent setting is modified.

Live terminal moves defer controller bounds while reparenting into the hidden destination. ConPTY receives the committed destination size, or the restored size after a failed move, rather than the temporary short viewport. The font regression verifies the actual resize event stream as well as retaining the completed pre-move size report through reset and subsequent input. Bounded diagnostics capture only the private fixture's renderer/output.

`GitStatus` reads metadata outside the UI thread with a four-second cancellation budget and bounded UTF-8 output. It resolves the executable from absolute PATH entries rather than the terminal working directory. Commands do not invoke a shell or run Git hooks, and disable lazy fetching and optional locks. Inherited `GIT_*` overrides cannot redirect the selected repository or enable trace-file writes. `DesktopWindow` serializes queries for its selected terminal, cancels stale requests, rejects stale results and stops its reader before pane teardown.

`Cmux.Terminal` owns the ConPTY transport previously exercised by `Prototypes/WindowsTerminal`; both the application and those existing tests reference the same library. `TerminalConnection` serializes transport operations. `WorkspacePane` defines the shared pane lifecycle; `TerminalPane` owns the trusted renderer/output queue and `BrowserPane` owns untrusted document navigation. `WebViewProfile` owns each isolated profile/browser lifetime. `DesktopWindow` owns mixed workspace/pane actions and native controls. Toolbar actions share these same methods with the integration tests.

`SessionSnapshot` defines the bounded data-only format, `SessionLayout` maps it to the existing pane actions/layout, and `SessionStore` owns serialized file access and replacement. The production entrypoint supplies the user-local store; integration tests supply a private store through the same constructor dependency.

WinForms is a thin Windows host here, and xterm.js is an initial VT renderer. This choice allows an interactive application using the verified transport and WebView2 stack. It does not establish Ghostty feature equivalence. Compare Ghostty settings, Unicode widths, image protocols, mouse modes, IME, accessibility and long-running workloads before choosing the final rendering strategy. Candidate provenance and differences remain in [the architecture comparison](../docs/windows-architecture-comparison.md).
